# Vita → GitHub → ACC → Codex

ACC проверяет комментарии GitHub каждые 5 секунд обычным Python-кодом.
Модель Codex вызывается только для нового задания. Команды status и cancel
обрабатывает ACC. Пока Codex занят, следующие задания ждут в очереди.

## Проверить сейчас

Канал: https://github.com/vitalydz/btc2g.github.io/issues/12

На Win11 запущен отдельный фоновый приёмник. Доступная цель — `acc-test`:
тестовая папка, read-only, отдельная сессия Codex с сохранением контекста.
Приёмник работает, пока компьютер включён и Python-процесс запущен.
Автозапуск при загрузке Windows не установлен.

Передайте Vita такую инструкцию:

> Для общения с ACC добавляй новый комментарий в Issue 12 репозитория
> vitalydz/btc2g.github.io. Начинай комментарий с `<!-- acc-inbox:v1 -->`,
> затем один блок JSON. runner: win11, target: acc-test. Для задания action:
> task и prompt с текстом пользователя; для состояния action: status; для
> отмены action: cancel. Читай ответы ACC в комментариях. Сообщай о завершении
> только после COMPLETED для соответствующего задания. Не редактируй уже
> отправленные задания и не отправляй дубликаты при задержке ответа.

Пример нового комментария (целиком):

````text
<!-- acc-inbox:v1 -->
```json
{"runner":"win11","action":"task","target":"acc-test","prompt":"Запомни слово МАЯК и ответь: слово запомнено. Не используй инструменты и не изменяй файлы."}
```
````

Следующее задание: «Какое слово я попросил запомнить?» — отправить в том же
формате с новым prompt. Статус и отмена:

````text
<!-- acc-inbox:v1 -->
```json
{"runner":"win11","action":"status","target":"acc-test"}
```
````

Для отмены замените `status` на `cancel`. Она отменяет очередь цели и
останавливает только процесс Codex, запущенный этим приёмником ACC.
Частичные изменения файлов после отмены нужно проверить.

## Проект и сессия

В ACC v1.3 есть кнопка **Vita / Codex**. Задайте репозиторий, доверенного автора,
номер Issue/PR, runner и локальные привязки целей. Пример:

```json
{
  "mpa": {
    "project": "C:\\Users\\vitly\\PycharmProjects\\MPA_04",
    "session_id": null,
    "sandbox": "workspace-write"
  }
}
```

`null` создаёт отдельную сессию на первом задании; ACC сохраняет её UUID и
продолжает именно её. Можно указать UUID существующей локальной сессии Codex CLI,
если она принадлежит выбранному проекту и сейчас свободна. Не запускайте в этой
сессии работу вручную параллельно с ACC. Автоматического выбора произвольного
чата Codex Desktop или сессии Codex Cloud здесь нет.

Для каждого ПК задайте свой runner (`win11`, `vitaly-win10`) и местные пути.
Работа через Codex Cloud возможна как отправка комментария в GitHub при наличии
доступа; постоянный приёмник в этой проверке работает на Win11.

По умолчанию GUI только принимает задания; **Approve selected** разрешает
конкретное задание. Флажок **Allow Vita's trusted tasks for this session**
включает выполнение заданий доверенного автора без отдельных подтверждений.
Только этот автор может отдавать команды; пути и session UUID из комментариев
не принимаются. При смене привязки используйте новый alias.

## Фоновый запуск и остановка

Используется установленный `codex` CLI с существующей авторизацией, Python и
GitHub credentials из ACC_GITHUB_TOKEN/GH_TOKEN/GITHUB_TOKEN, gh или Git
Credential Manager. Токены не записываются в настройки и комментарии.

Из папки ACC_1_3:

```powershell
python acc_codex_inbox.py --repo vitalydz/btc2g.github.io --owner vitalydz --runner win11 --issue 12 --targets "$env:USERPROFILE\.acc\vita-inbox-targets.json" --allow-tasks
```

Остановка такого приёмника из другого терминала:

```powershell
python acc_codex_inbox.py --repo vitalydz/btc2g.github.io --owner vitalydz --runner win11 --issue 12 --stop
```

Дождитесь выхода процесса перед запуском через GUI. Два приёмника одной
очереди на этом ПК одновременно не запускаются. В GUI используйте Stop inbox.
Не запускайте ручные/плановые задания в том же рабочем каталоге параллельно.

Журнал и session UUID: `%USERPROFILE%\.acc\inbox-*.json`.
После сбоя выполнявшаяся задача получает UNKNOWN и не повторяется автоматически;
работа с этой целью/проектом блокируется. Проверьте процесс, файлы и результат
вручную перед восстановлением журнала. Не удаляйте журнал для повторной отправки.

Интервал 5 секунд — между завершением запросов, не гарантия доставки за 5 секунд.
ETag уменьшает повторную передачу данных; ошибки сети и лимиты API вызывают
задержку повторных запросов. Результаты публикуются в выбранном GitHub Issue;
для приватных задач используйте приватный репозиторий. Маскирование известных
форматов токенов не заменяет проверку содержимого ответа.

## Проверено 25.11.2026

На Win11 реальная цепочка GitHub → ACC → установленный Codex CLI → GitHub:
два последовательных задания завершены, второе вернуло слово CEDAR из первого
в той же сессии. После 45 опросов было ровно два запуска модели. Команды статуса
обрабатываются без вызова модели. Автоматические тесты проверяют очередь,
отмену, изменение комментариев, перезапуск и защиту от повторного выполнения.
Голосовой интерфейс Vita пользователю предстоит проверить самостоятельно.
Win10/VITALY PC в этой проверке не участвовал.
